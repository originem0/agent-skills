## 核心命题
- 缓存的本质是用一致性风险换延迟收益，所有缓存头都是在调这个交换的参数
- 新鲜度判定（max-age/Expires）省的是整个请求，协商验证（ETag/304）省的只是响应体

## 概念地图（Encoding 工作台）
- Cache-Control --[包含]--> max-age / no-cache / no-store
- max-age --[决定]--> 新鲜度（fresh 期内不发请求）
- 过期 --[触发]--> 协商验证（If-None-Match / If-Modified-Since）
- ETag --[支撑]--> 304 Not Modified（内容指纹一致则不传 body）
- no-cache --[允许存储但]--> 每次使用前必须协商验证

## 逻辑链
资源过期 → 浏览器带 If-None-Match 发条件请求 → 服务器比对 ETag → 一致回 304（无 body）/ 不一致回 200（新内容+新 ETag）→ 浏览器更新缓存与本地元数据

## 关键例子与反例
- 例：刷新页面时静态资源大量 304 —— 协商验证在工作
- 反例：Ctrl+F5 强制刷新绕过缓存，全部 200 —— 说明缓存判定可被请求头覆盖
