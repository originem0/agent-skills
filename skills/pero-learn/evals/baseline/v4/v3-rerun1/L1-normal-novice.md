## 教练（第 3 轮）
[递归] | 阶段：初始化 | 进度：[0/0]

可以用例子学。开始动手写递归时，我会先给你看一个完整写好的例子，你照着写一个只改了一处的，之后再慢慢少给提示。但从头到尾讲一遍这种方式我不用。学递归有个常见的坑：看别人写的时候每一步都很顺，轮到自己写，第一行就不知道怎么下笔。看例子学得快，不代表自己写得出来。讲得越顺，越容易以为自己懂了。

讲到什么程度，也要看你学了拿来做什么。应付考试、面试刷题、看懂别人的代码，要学的范围差别很大。所以还是这两件事。你回答完，我就建好学习项目的目录，你在那个目录里开一个新会话，就正式开始学：

1. **目的**，选个字母：A 课程/考试　B 面试刷题　C 看懂别人代码　D 手头有具体问题要解决　E 说不清，就想弄明白
2. **起点**：下面这段代码运行后会打印什么？看不懂就写"看不懂"，这也是有用的答案，我会据此决定第一课直接学递归，还是先把函数补扎实。

```python
def double(x):
    return x * 2

def f(n):
    return double(n) + 1

print(f(3))
```

回一行就行，写上选的字母和你的答案。

## 教练（第 4 轮）
[递归] | 阶段：初始化 | 进度：[0/0]

你写的"f(x) 就是 f(里面那层) + 1"，意思是：整个列表的深度交给里面那层去算，算完再加 1。思路是对的，这就是递归的想法。但它还不完整。照这个式子去算具体的列表，有两种情况它处理不了，两种都藏在"里面那层"这几个字里。

你一开始说递归完全不懂，可这句话说明你不是从零起步。我会把这句话原样记进项目文件，作为你的起点。第一课就从那两种情况开始：你拿具体的列表，照自己的式子一层层往下算，自己撞上它们。上次那段函数代码也挪到第一课再看。

现在只差学习目的。我先替你暂定一个：学完能自己写出简单的递归函数，并讲清它每一步在算什么。同意的话就回"行"，我在当前目录下建 `recursion/`，你到那个目录里开个新会话，就能开始第一课。如果你其实是为了考试、面试，或者为了看懂别人的代码，要学的范围会不一样，告诉我是哪一种。
