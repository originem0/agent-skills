直接说：

- **INNER JOIN**：只保留两表在连接条件上匹配成功的行，匹配不上就整行消失。
- **LEFT JOIN**：左表的行全部保留；右表匹配不上时，右表那几列填 NULL。

区别就一句话：左表里没匹配上的行，留不留。

例子：`users LEFT JOIN orders ON u.id = o.user_id` → 从没下过单的用户也出现在结果里，订单列全是 NULL；换成 INNER JOIN，这些用户整行不见。

走之前花 10 秒验证一下你真拿到手了——这也是这个区别在实战里最常翻车的地方：

```sql
SELECT u.name
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.status = 'paid'
```

这个查询的结果里，"没下过单的用户"还在吗？为什么？

好，给答案：**不在了。**

原因：没下过单的用户，`o.status` 是 NULL。`WHERE o.status = 'paid'` 要求这个值等于 'paid'，而 NULL 跟任何值比较都不成立，所以这些行被 WHERE 过滤掉了。

结果就是：你写了 LEFT JOIN，但 WHERE 里对右表列的条件把它悄悄变回了 INNER JOIN。这是 LEFT JOIN 在实战里最常见的翻车方式——想要"所有用户 + 他们的已付订单"，拿到的却是"有已付订单的用户"。

修法是把条件从 WHERE 挪进 ON：

```sql
LEFT JOIN orders o ON u.id = o.user_id AND o.status = 'paid'
```

ON 里的条件只影响"右表哪些行参与匹配"，匹配不上照样保留左表行；WHERE 是对拼好的结果整行做删除。

不对，而且是反的：**LEFT JOIN 不去重，它还会增加行数。**

JOIN 的机制是：左表每一行，跟右表所有匹配上的行**各配一次**。一个用户有 3 笔订单，LEFT JOIN 之后这个用户出现 3 行。所以经典事故是：`SELECT COUNT(*) FROM users LEFT JOIN orders ...` 数出来的不是用户数，是订单数（外加无订单用户各 1 行）。

"保留左表全部行"说的是**至少一行、不会丢**，不是"恰好一行"。你笔记大概是把这两件事记串了。真正去重要靠 `DISTINCT` 或先对右表 `GROUP BY` 再 JOIN。

这句笔记要是背着上了面试，比不知道还糟——面试官一听"自动去重"就知道你没跑过真数据。把笔记那行改掉。
