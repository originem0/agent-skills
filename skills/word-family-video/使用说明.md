# 词族讲解视频 · 使用说明

## 它是什么

把 `word-family` 做好的词族课，变成一支 5 分钟以内的讲解视频。每支视频的口播、讲解关系和分镜都在 `projects/<项目>/script.md`。你可以自己审，也可以明确说「脚本由你审核，我只看最终成果」，让 agent 核实来源、审稿、修正并直接出片。

- **脚本先行**：从已有生活经验里揭开意外联系，按理解难点选择路线，适量比较易混词根词缀，在过程中归纳关系。方向、演变、场景、对照都可借用和混用，不按每词固定流程或讲法配额写稿。真实事件和图片附出处。
- **画面**：文字、照片、图形与动作按本段关系组合。镜头有稳定编号，语音触发点可以独立命名。不会自动把每个词塞进一张卡，也不强制倾斜或持续推近。图片裁切保留比例，人物在需要身体动作时出场。预览、定格和成片共用同一份编译结果。
- **顶部导航**：显示当前讲的词和此前引入的词，回到旧词时可重新高亮。词多时保留当前附近的一组，不把未来词提前铺满，也不把第一次出现当成已经讲完。
- **配音**：微软 edge-tts「云健」（免费，默认 1.2 倍语速），按句合成、逐词对时，念到哪个词，画面就在那一刻动。

分镜样片（本地生成，不进 git）：`projects/capit-storyboard/capit-storyboard.mp4`（4 分 48 秒）、`projects/port-storyboard/port-storyboard.mp4`（4 分 31 秒）。两份 `script.md` 展示意义分支与方向参照的不同编排。质量依据见 [capit 标准示例](references/capit_benchmark.md)，不要把样片的镜头数或布局当配额。

## 安装

和 word-family 一样，在 agent-skills 仓库里运行安装脚本（或手动建联接）：

```powershell
New-Item -ItemType Junction -Path "$env:USERPROFILE\.claude\skills\word-family-video" -Target "D:\Development\Automation\agent-skills\skills\word-family-video"
```

依赖：

```bash
pip install edge-tts numpy playwright      # Playwright 直接用本机 Chrome/Edge，不用另下浏览器
pip install pillow faster-whisper          # 可选：定格总览图、读音检查（首次检查会下载 large-v3-turbo，约 1.6GB）
```

另需 ffmpeg 在 PATH 里，以及同目录下的 word-family skill。

## 怎么用

在 Claude Code 里：

```
/word-family-video 给 cap 写视频脚本
/word-family-video 给 tract、pend、spect 写视频脚本      # 几课一起写
```

1. **写稿**：agent 为每课写 `script.md`，自动检查改到干净。常规审核交付脚本与试听；授权自行审核时继续走完整出片流程。
2. **你审**：直接改 `script.md`，或在要改的地方写一行 `>> 批注`，然后说"按批注改"。想让 AI 再挑一遍毛病就说"审一遍"（可选，默认不审）。
3. **通过**：满意了说"通过"，agent 会出定格图自检、渲染、做读音检查，告诉你成片路径。
4. **回头改**：成片看完不满意，照样改脚本或写批注。常规审核需再确认；当前任务已授权自行审核时，由 agent 复核并记录新指纹后重新出片。

本机的默认 Python 3.15 与已安装的 NumPy 扩展不兼容，项目已用现有 Python 3.14 建好 `.venv`，复用现有依赖。在此目录运行命令时，用 `.venv\Scripts\python.exe -I scripts/video.py …`。没有新增依赖或改动系统 Python。

## 手动操作

```bash
python scripts/video.py brief   cap        # 写稿素材：词源、可用画面、每个词的触发词、时长预算
python scripts/video.py plan    cap        # 检查 + 配音 + 时间轴 + 试听音频，打印每个节拍
python scripts/video.py mark    cap approved   # 记录你的确认（只在你说"通过"时用）
python scripts/video.py mark    cap approved --by "用户授权 AI 审核"   # 仅在你明确授权自行审核并直接出片时用
python scripts/video.py preview cap        # 浏览器预览：打开 build/preview.html，画面 + 声音 + 拖动条，不用渲染
python scripts/video.py stills  cap        # 每个节拍一张定格图 + 总览 stills/_sheet.jpg，并自检
python scripts/video.py render  cap        # 成片 → projects/cap/cap.mp4（只渲染确认过的脚本）
python scripts/video.py check   cap        # 读音检查
python scripts/video.py plan    port --project port-cables   # 同一课的独立版本，脚本写在 projects/port-cables/
python scripts/video.py preview port --project port-cables   # 后续命令保持同一 --project
python scripts/video.py photo   cap get https://…/图.jpg name   # 下载网上的图片到 media/，打印可粘贴的 [photo] 行和署名
python scripts/video.py status             # 所有课的状态、时长、批注数、能否出片
```

脚本写法见 `references/script_guide.md`。

可选文件头 `seed` 固定视觉选择。`> 镜头` 可选左图、右图、居中或词节拍的大字；`> 动作` 可调正常、轻、明显或静止，`> 动作点` 配合解说里的 `{触发词}` 对时。`[recap: 已讲词 | 已讲词]` 在过程中收拢关系，不承担新词讲解；不同源词继续用 `[pair]`，不会混到本家小结里。

## 声音和语速

- 默认音色云健（`zh-CN-YunjianNeural`），默认语速 +20%（约 1.2 倍）。
- 调整：`--rate +10%`（嫌快）、`--rate +0%`（原速）、`--voice zh-CN-YunxiNeural`（换音色）。`plan`、`preview`、`stills`、`render`、`check` 都接受这两个参数，同一支视频前后要用同一组参数。
- 每组「音色 + 语速 + 句子」单独缓存，换参数后第一次运行会重新配音（需联网）。

## 读音检查

`check` 用 Whisper large-v3-turbo 把每句配音转写回文字，结果分两类：

- **可能读错**：两遍识别都没听出这个词，先去听那一句；
- **读得可能不够清楚**：第一遍没听出，把它当热词提示后才认出。

确认读错的，在 `script.md` 文件头的 `say_as` 里写替换（只改配音，字幕不变），例如 `say_as: retractable → re-tractable`。这算改了脚本，按当前任务的审核授权重新确认并记录指纹。3 个字母以内的前缀（at、ad、dis）不检查：edge-tts 没法逐词标音，这类读音只能靠改写文字。cept、ceive 这类词根片段 Whisper 也常听成 set、save，需要结合音频判断。

## 时长规则

- 目标 ≤ 4 分 50 秒，上限 5 分钟。超了由写稿方删节拍，删掉的主词写进文件头 `skip`（网页版里仍有）。
- 不自动删减、不靠加快语速：审的是什么，渲出来就是什么。

## 文件夹结构

```
word-family-video/
├─ SKILL.md                     agent 的工作流程
├─ 使用说明.md                  本文件
├─ assets/story_frame.html      分镜画布、字体、字幕和署名区域
├─ assets/scene_player.js       执行明确节点和时间轨道，支持任意拖动
├─ assets/actors.js             视频人物的关节曲线、重心、握持与有限动作
├─ scripts/video.py             brief / plan / review / mark / photo / status / preview / stills / render / check
├─ scripts/script_md.py         脚本解析、检查、审核状态
├─ scripts/storyboard.py        讲解关系、画面引用与收束校验
├─ scripts/scene_compile.py     分镜与声音时间 → 自足画面
├─ scripts/legacy_import.py     旧稿导入同一编译器
├─ scripts/provenance.py        课程、素材、代码与声音设置的审核指纹
├─ scripts/test_script.py       单元测试：python -I scripts/test_script.py
├─ references/script_guide.md   脚本写法（主线、讲法、事实与出处、画面块、读音）
├─ references/storyboard_guide.md 新分镜语法与可组合画面
├─ references/review_brief.md   可选的 AI 审稿要求
├─ evals/                       行为测试用例
├─ projects/<词根>/             每支视频一个目录：script.md、review.md、media/（进 git）+ build/、stills/、mp4（不进 git）
└─ cache/tts/                   配音缓存（不进 git）
```

`plan` 写出 `build/timeline.json` 和 `build/film.json`，后者包含已选画面、嵌入图片和绝对时间轨道。新稿格式见 [分镜指南](references/storyboard_guide.md)。原有脚本继续可读，由适配层转换后使用同一播放器。

审核还记录课程、图片、画面代码、音色与语速。相关输入变化后要按既有授权重新检查并 `mark`；只有旧文本指纹的稿件也要补做完整审核。`render` 检查动作前、中、后，先输出临时成片，时长与输入核对通过才替换旧版。`build/render.json` 保存输入、编译结果和视频的哈希。预览音频按脚本、音色和语速共同缓存。

## 借鉴与出处

- 「先画线稿、后上色」「元素绑定到某一句解说出场」的思路来自 [geeklee/srt-whiteboard-animation](https://github.com/geeklee/srt-whiteboard-animation)（MIT）。它处理的是位图（OpenCV 骨架追踪），我们的线稿本来就是矢量，所以只借了思路，用 SVG 描边动画实现，没有搬代码。
- 「逐句配音、用配音时长排时间线、逐帧确定性渲染」的做法与 [narrated-slide-video-toolchain](https://github.com/alex454-byte/narrated-slide-video-toolchain)（MIT）相同。
- 弹簧动效的物理参数与 [Remotion](https://www.remotion.dev/) 的 `spring()` 相同（只借参数，渲染仍是 Playwright 逐帧截图）。
- 读音回听检查的思路来自 [explainroo](https://github.com/vincentsch/explainroo)（MIT）。

## 限制

- 配音需要联网（edge-tts 是免费的在线服务）；断网时已缓存的句子仍可用。
- 配色与字体统一，路线、构图和人物动作可调整；edge-tts 不支持自定义 SSML。
- 渲染是逐帧截图，一支 5 分钟的视频在无独显的笔记本上要几分钟。
