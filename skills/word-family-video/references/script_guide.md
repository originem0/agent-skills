# 视频脚本写作指南（projects/<课>/script.md）

脚本是每支视频的成稿：先写给耳朵听，再交给画面。动笔前先运行 `video.py brief <课>` 读素材。

2026-10-30 起，新稿按 [分镜格式](storyboard_guide.md) 写稳定编号的 shot、讲解关系和明确画面。本文的教学、核实、口播与检查原则继续适用；下文的旧画面块语法用于读懂和导入已有稿，不再作为新稿模板。新稿不受每词一张卡、默认例句位置或旧镜头参数限制。

与 word-family 共用 `references/teaching_principles.md`。先确定观众已有的经验、值得解释的意外联系和本课的理解难点，再组织路线、差异与画面。固定 HTML 卡片是素材，不是视频分镜。

写稿和自查同时对照 [capit 标准示例](capit_benchmark.md)。丰富度来自有用的联系充分展开，连贯性来自每一步承接并增加理解；举例、图片、例句和结尾要一起完成这条路线。

目录：一、定主线 · 二、每个词换讲法 · 三、真实图片 · 四、口播语言 · 五、事实与出处 · 六、格式 · 七、画面块 · 八、时长 · 九、交审前自查 · 十、AI 审稿（可选） · 十一、读音

## 一、定主线（写进文件头 spine）

主线由材料、焦点问题和理解难点决定，不由课程卡片的顺序决定。下面是可借用的思路，可以混用或另定路线，不是必须选中的四种模板。

| 主线 | 怎么认 | 怎么排 | 例 |
|---|---|---|---|
| 方向型 | 词根是一个身体动作，前缀给它换方向 | 同一个母画面换方向，方向尽量成对（往外/往回、往一起/往两边） | tract 拉：attract、distract、extract、contract |
| 演变型 | 词义分几步漂移，后一步从前一步长出来 | 分幕，每幕一个 `[title]`，每幕的词共用这一步的画面 | pend：挂 → 挂上秤称 → 称出去付钱 |
| 场景型 | 词根长在某个领域里 | 带观众在场景里走一圈 | jud：法庭里的 judge、verdict、prejudice |
| 对照型 | 一课围绕反义或容易混的成对词 | 用 `[pair]` 成对讲，讲差别 | import / export、include / exclude |

spine 写一句话，说明实际路线和要解开的关系，例如「从随身用的布追到头，再区分带头的人与抓东西」。无需套分类名。每拍应有理解上的作用，允许一段持续动作中拼词、先对比再溯源，或先进入意义分支再回到母画面。

### 分割之后，在过程中整合

一组关系讲清、对比完成或意义即将转折时，短暂归纳哪些没变、哪些变了，再接入下一段。后一次回扣带上新关系，母画面在不同语境里多次出现。只带已讲清的词和关系，不提前堆满全家词表。

小结可以复用动作、用成对画面或局部关系图；无需每次章节卡、无需每几个词固定插入。解释交给声音，画面呈现关系，避免又把解说抄一遍。过程整合落实到视频，不改变 HTML 的固定流程。

刚讲完一对词，不因完成了两个词就立刻再复述一次。回扣可以融入下一段的承接句；只有收拢后能帮助跨过转折，才单设小结节拍。连贯不要求全片困在同一场景，母题在不同日常对象间自然展开也能连成一条线。

## 二、每个词换讲法

按材料选择讲法；多个方案同样合适时可以换一种或随机选，不要求每个词枚举固定数量：

- 真实事件：2020 年 3 月 11 日 NBA 宣布 suspending 赛季（要来源，见第五节）
- 物件特写：饮水机 water dispenser、按一下就缩回的 retractable pen
- 一词多义分叉：contract 既是收缩又是合同——拉到一起的是东西还是人
- 历史演变：spend 是拉丁语 expendere 被磨短的样子
- 反差：长得像却不同源（pen 钢笔来自羽毛），或者两个熟词的矛盾
- 想象小剧场：荒诞好记的小画面；是联想就写 `> 注：联想`
- 冷知识、数字：要来源
- 两词对照：extract 与 retract 一出一回，用 `[pair]`
- 真实标题或原话：要来源

连续讲解可以共享同一个场景或动作，只要关系在发展。比较同批及相邻作品的实际入口、路线、过渡句和构图；不要只换几个例词却沿用同一套流程。讲法与图片不设配额，真实事件按需要用。随机选择落到脚本后保持稳定，不能每次预览或渲染重新抽。

易混词根词缀在容易误判处适量对照：说清相似之处和关键差异，再回到主线。对比双方核实词源与用法，不把反例混进同一家，也不要求每课必有一个陷阱。

## 三、真实图片

照片只做一件事：让观众认出"这个我见过"。所以照片只给观众在现实里见过的东西用：手机界面、包装上的字、最近发布的产品、正在发生的新闻现场。观众没见过的东西（古代插图、文物、抽象概念）用课程线稿，线稿能画出方向和动作，照片画不出"往外搬"。

认出东西之后，观众还应看见当前要解释的关键部位或关系。讲接口就让接口可辨，讲盖头布就呈现布和头的关系；仅有相关物件或两个单词不够。例句也应落在本段真实用法上，使熟悉场景与词义互相印证，不能只作为词卡底部的装饰。

- 没有配额：全片零到三张都正常。没有贴切的就不用，不为了"有图"硬塞。
- 优先近几年、学习者熟悉的东西：新发布的产品、App 界面、正在发生的新闻、日常包装和标识。具体产品与发布日期先核实；老图只在历史本身就是要讲的内容时才用。
- 视频不公开发布，取图不限于维基共享资源：新闻页、官网新闻稿、产品页上的图都可以用。
- 图必须一眼看出就是解说说的那个东西；拿不准就不用。
- 署名必填：维基共享资源的图写作者和许可；网上直接取的图写来源网站和取图日期，例如 `> 署名：来源：apple.com，2026-10-28（https://…）`。

      python -I "$SKILL/scripts/video.py" photo <课> search "water dispenser"            # 搜维基共享资源，看 _sheet.jpg 挑图
      python -I "$SKILL/scripts/video.py" photo <课> pick "water dispenser" 3 dispenser    # 存成 media/dispenser.jpg
      python -I "$SKILL/scripts/video.py" photo <课> shot https://…/news nba-news           # 网页截图，必要时加 --clip x,y,宽,高
      python -I "$SKILL/scripts/video.py" photo <课> get https://…/图片地址.jpg duo         # 直接下载网上的图片，存成 media/duo.jpg

- 搜维基共享资源时，搜索词用英文，写具体的实物或场景（"retractable pen"、"airport baggage claim sign"），比抽象词好找。
- 这几个命令都会打印两行，直接粘进脚本：`## 标题 [photo: media/xxx.jpg]` 和 `> 署名：…`。
- 事件现场想铺满全屏，加 `> 版式：整屏`。
- 课程开场有照片的，可以用 `[photo: opening]`，但不是非用不可，见第四节「开场的画面」。

## 四、口播语言

- 一行就是一句配音，不超过 40 字；长句短句交替，可以有四五个字的短句。
- 反问按需要使用；重复的起句、转场和收束会让人听出模板。避免把每词都写成“这不就是……吗”，不按反问数量设计内容。
- 不用转场套话（"下面我们来看""接下来是""我们再来看"）。用承接内容的句子过渡：「如果吊在半空的，是你头顶上的一块石头呢？」
- 不念卡片：不说"字面画面是""词性是"；括号、符号、v./adj. 不进解说。
- 英文词直接写，前缀不加连字符（写 sub，不写 sub-）。
- 开场从课程事实和生活素材重新选择，可借用 word-family `references/openings.md` 的思路，但不必沿用课程类型。先呈现具体经验或值得解释的矛盾，在获得理解支撑时揭开关系；结尾收住焦点问题，不必统一一段词表加一句口号。
- 每个 `[word]` 词卡默认在释义下面放课程里的例句（`ex`，英文 + 中文，目标词高亮），解说可以念也可以不念。想换成别的短语就写 `> 例句：tech {support}`，花括号标出目标词：解说念到了就在念到那一刻上屏，没念就跟着释义出现。画面太挤不想要例句，写 `> 例句：-`。

开场的画面：开场类型定的是钩子讲什么，第一拍用什么画面要另外挑。同一批视频之间要轮换，不要每支都用一张照片开场：

| 画面 | 块 | 适合 |
|---|---|---|
| 照片 | `[photo]` | 观众见过的实物、界面、现场 |
| 线稿小剧场 | `[scene: opening]` | 想象小剧场，或一个动作、场景 |
| 标题、原话卡 | `[event]` | 时事、真实引语 |
| 两词对照 | `[pair: A \| B]` | 双词矛盾 |
| 大字 | `[title]` | 视觉谜题、熟词拆名：把那个词、那处拼写直接打在屏幕上 |

按材料选择并比较相邻视频，照片开场没有比例限制。课程开场配了照片，也不等于视频要用照片开场。重复构图有叙事作用时可以保留，变化不是逐拍换皮。

改写前后（suspend）：

> 改前：箱子吊到半空……事情悬在那里不往下走，这不就是暂停吗？
>
> 改后：2020 年 3 月 11 日晚上，NBA 发出一份声明，正文就几行。最要紧的是这个词：suspending。不是取消，也不是照常，而是 until further notice，等通知。一整个赛季，就这么被吊在了半空。

## 五、事实与出处

- 年份、日期、数字、引语、事件：用网页搜索找到原始报道并打开核实，在所在节拍写 `> 来源：URL（日期）`。没有来源，`plan` 会报错。
- 词源说法只能来自课程素材（`brief` 里的"词源"）或 word-family 的 `scripts/etym.py`；新查的写 `> 来源：etymonline <词>`。
- 找不到可靠来源的说法，删掉。不许凭记忆补日期、数字、引语。
- 只陈述事实，不评论、不站队。

## 六、格式

    ---
    lesson: pend
    spine: 演变——挂 → 挂上秤称 → 称出去付钱
    seed: 27
    skip: append（时长不够，网页版里有）
    say_as: live → laiv
    ---

    ## 一场停摆 [event]
    > 事件：NBA 官方声明 · 2020-03-11
    > 原文：The NBA is {suspending} game play … {until further notice}.
    > 来源：https://official.nba.com/nba-to-suspend-season-following-tonights-games/
    2020 年 3 月 11 日晚上，NBA 发出一份声明，正文就几行。
    最要紧的是这个词：{suspending}。

    ## suspend [word: suspend]
    {sub}，从底下往上；碰到 p，它常常写成 {sus}。
    {pend}，挂。

    把事情吊起来，不让它落地，就是 {suspend}，暂停。
    学校里的停课处分，英文叫 suspended from school。
    > 例句：{suspended} from school

- `## 标题 [画面块]` 或 `## 标题 [画面块: 参数]` 开始一个节拍。标题写给人看；`[title]` 节拍直接把标题显示成章节卡。
- 普通的一行 = 一句配音。`{词}` 是触发点：念到它的那一刻画面动作；花括号不进字幕，也不念。
- 空行 = 段落停顿（比句间停顿长）。
- `> 键：值` 是画面数据和出处，不念：`事件`、`原文`、`来源`、`署名`、`版式`、`释义`、`例句`、`注`，以及可选的 `镜头`、`动作`、`动作点`。
- `> 例句：英文短语`：换掉词卡默认的课程例句，`{}` 标出目标词（高亮）。只能用在 `[word]`、`[scene]`、`[photo]` 节拍里，每拍最多一条。解说念到这个短语，就在念到那一刻上屏；没念，就跟着释义出现（`[scene]`/`[photo]` 节拍里从第一句开始）。超过 8 个英文词会提醒。写 `> 例句：-` 不放例句。
- `[pair]` 里有课程外的词时，用 `> 释义：词 = 义` 给它配释义（一行一个词）。
- 当前只讲某个意义分支时，`[word]` 可写 `> 释义：本段的真实义项`；`[pair]` 用 `> 释义：词 = 本段义项` 覆盖。省略则显示课程的常用义项，不自动截取。只按课程事实或已核实用法取舍，不能为配合故事改词义。
- `>> ……` 是审稿人或用户的批注，不念；处理完要删掉，留着就不能出片。
- 文件头：`lesson`、`spine` 必填；`status`、`checked` 由 `video.py mark` 维护，不要手改；`skip` 写没讲的主词和原因；`say_as` 只改配音，字幕不变。可选 `seed` 为 0–4294967295 的整数；省略时由脚本指纹确定选择。
- 每个课程主词要有 `[word]` 或实际陈述的 `[pair]` 讲解，或者写进 `skip`。只在开场问题中点名，或出现在地图和小结里，不算已经讲清。
- 一课做多个版本时，命令都带同一个 `--project 版本名`。文件仍写 `lesson: 原课程名`，读同一份课程 JSON；不要为不同视频复制课件。

## 七、画面块

先选能解释关系的画面，再选块和动作。物件、照片、静态线稿、文字特写与关系图都可以承担主画面；需要动作说明方向或接触时才安排人物动起来，不把火柴人或动效当作逐拍必需品。

| 块 | 写法 | 位置 | 触发点 |
|---|---|---|---|
| 章节卡 | `[title]` | 整屏 | — |
| 线稿 | `[scene: 词]`，也可 `anchor` / `opening` / `finale` | 左边空着时居中放大；有词时在右侧 | — |
| 照片 | `[photo: opening]` 或 `[photo: media/文件]`（课程外的要 `> 署名`） | 同上；`> 版式：整屏` 时铺满 | — |
| 词素拼合 | `[word: 词]` | 左侧，可与右侧线稿、照片同屏 | `{词素}` 入场；先念原形 `{sub}` 再念 `{sus}` 会出现变形；`{整词}` 合拢并出释义 |
| 引文/事件卡 | `[event]` + `> 事件` `> 来源`（`> 原文` 可选，`{}` 标高亮） | 整屏 | 解说里与高亮相同的 `{片段}` |
| 两词对照 | `[pair: A \| B]` | 整屏 | `{A}`、`{B}` |
| 局部小结 | `[recap: A \| B]`，最多 4 个词 | 整屏，只带已讲主词或 finale | `{A}`、`{B}`，或按句子出现 |
| 家族图 | `[map]` | 整屏 | 提到哪个词，哪个节点亮 |
| 迁移题 | `[quiz]` | 整屏 | `{答案词}` 揭晓 |

- `[scene]` / `[photo]` 接 `[word]` 是一种可用组合。可以共享连续场景、先用成对对照、在动作发展中拼词，再回扣母画面；不要把这种组合复制到所有词。
- 整屏块出现时，左边的单词会淡出。
- 屏幕上的字只有单词、词素小注、本段释义（一个词性一行）、例句、引文原文、章节标题。解释交给声音，未展开的意义分支留在课程或后面的讲解里。
- `[word]` 里能用哪些触发词，`brief` 里每个词都列出来了。

局部小结可写 `> 版式：对照` 或 `> 版式：分支`，省略时稳定选择。它只回扣本课已经讲清的主词或 finale；不同源词仍用 `[pair]` 对照，不能挂到本课词根下面。小结不承担主词覆盖，不提前给未知词铺图。

场景、照片和词节拍可写 `> 镜头：自动`、`右图`、`左图`；词节拍还可写 `大字`，不出现人物卡片；独立场景或照片可写 `居中`。同一场景连着讲时保留构图，改变要服务当前关系。

`[word]` 紧接场景或照片时沿用那张图，直接从一个词换到另一个词时默认用新词自己的线稿。要明确共享已有场景，写 `> 画面：沿用`；要选别的本课线稿，写 `> 画面：anchor` 或一个线稿词名。大字镜头不显示舞台，不与画面指定混用。

有线稿人物时，`> 动作：正常`、`轻`、`明显`、`静止` 控制动作幅度。想在说到某处时动作，写 `> 动作点：托`，并在解说里写 `{托}`；不写则从场景出现后开始。动作是有限的一次过程，结束后停留；残影与站立背景人物保持静止。

角色搬运或行走需要位移时，从 word-family 的场景中读取明确的 `motion.from` 与终位；有 `follow` 的物件与角色同行，步态在地面上交替。单个动作点尽量在句子中只出现一次，避免同一个词的两次发音让对时含混。不要把队伍里的灰色人物自动解释成主角的原位。

画面上实际会发生什么（写稿时心里有数）：

- **主图居中**：左边没有内容的节拍（单独的 `[scene]`、`[photo]`），线稿或照片居中放大（照片保持比例，大约放到 1400×720 以内；线稿约 1.5 倍）。母画面 `[scene: anchor]` 左边有词根，是分屏。
- **主图让位**：`[word]` 沿用前一拍的舞台（线稿或照片）。前一拍是居中的主图时，先保持居中，念到第一个词素（`{词素}` 触发点，没写就从第一句开始）时缩到右侧，左边同时开始拼词——讲场景时场景最大，开始拆词时场景让位。拼完词，下一拍又只剩同一张图时，它平滑回到居中。前一拍是整屏块或整屏照片时，舞台换成这个词自己的线稿。紧接着再写这个词的 `[scene]`，左边的词会留着（分屏）。
- **构图**：同一种构图（主图居中 / 左词右图 / 同一种整屏块）连续 4 拍以上，`plan` 会提醒：中间插一个只放画面的节拍，或换成整屏块。
- **卡片**：照片带白边、线稿垫一张浅纸，按节拍有固定的小倾斜（同一张图连着几拍角度不变）；整屏照片不倾斜。
- **例句**：分屏时在左栏单词和释义下方；主图居中时在主图下方。
- 前缀按意思入场：「上」从上方落下、「下」从下方升起、「外/出」向外滑出、「里/进/入」向里收进、「回」由外收回、「一起」合拢、「分开」弹开、「朝向」由左靠近、「前」向前推、「中间/穿过」从右侧越过、否定类原地缩回。所以触发词的时机要落在说这个意思的那一刻。
- 词卡和两词对照默认显示课程常用义项；用 `> 释义` 明确选择本段分支时，只显示所选内容，词性各占一行。没写 `{整词}` 时，最后一句开始时合拢。
- `[pair]`、`[quiz]` 没写触发词时，按句子依次出场、最后一句揭晓；`[quiz]` 揭晓前只显示等号右边的拆法。
- `[event]` 的原文按 54 号字居中显示，超过两行会显得挤：`> 原文` 只摘关键的一两句。
- `[map]` 里解说没点名的词，节拍开头依次亮起；点名的在念到时亮。
- 照片下方显示署名（不显示网址，网址留在脚本里）。照片会缓慢推近约 6%，四边各裁掉约 3%：网页截图要在文字四周留出空白（例如截图时左右各多留 50px），否则贴边的字会被切掉。
- 人物动作看关节、重心和接触关系：拉要有抓住后用力，推要前倾，递要有伸臂和停留，走要有膝与落脚。手和绳子、道具必须相连，静止时不无意义地摆动。动作前、中、后都要抽看，逐笔画出和整张图缩放不能代替身体动作。
- 写完跑 `stills`：它会自检出界、重叠、箭头缺失、裂图，有问题按提示的节拍改。例句太长压到右边的图，就是在这里报出来的。

## 八、时长

目标 ≤ 4:50，上限 5:00（当前语速 +20%）。参考：开场 + 母画面约 60 秒，每词 25–35 秒，回扣 + 家族图 + 结尾约 40 秒。超时就删：先删次要词的展开，再删整个词；删掉的主词写进 `skip`（附原因，例如"时长不够，网页版里有"）。不靠加快语速。

## 九、交审前自查

- [ ] 开头 10 秒里有一个观众见过的具体东西或一个矛盾；开场画面没有为了"有图"而用照片
- [ ] 主线在节拍标题里看得出来
- [ ] 对照 capit，值得讲的联系展开充分，每次举例、换图或加入例句都增加理解；没有为了缩短或变换形式削弱内容
- [ ] 意外来自有依据的日常联系，必要的相似词根词缀对比确实纠正了误解
- [ ] 分割节点有理解支撑，过程小结连接已讲关系并承接新分支
- [ ] 与相邻作品相比，入口、路线、句式和画面有实际变化，或复用有叙事理由
- [ ] 每张照片都是观众在现实里见过的东西，而且有署名；没有贴切的就没用
- [ ] 每个年份、数字、引语、事件都有来源
- [ ] 屏幕上的字没有和解说逐句重复；词卡的例句合适（课程例句不合适就用 `> 例句` 换掉或 `> 例句：-` 关掉）
- [ ] 关键关系能在画面里看出来；人物和动作确有用途，没有拿两个单词或泛用火柴人代替该画的关系
- [ ] 结尾回答开头的问题，完整收拢本片已展开的主词和重要分支，开场联系与刚讲的新分支没有落在总结之外；反例保留家族边界，未知词不提前塞进图

## 十、AI 审稿（可选）与处理意见

AI 审稿不是默认必经步骤。用户要求审稿或明确授权「你审核，我只看最终成片」时：

1. `video.py review <课>` 生成审稿包 `build/review_brief.md`（审稿要求 + 课程素材 + 带行号的脚本）。
2. 按授权由当前 agent 或可用的独立审稿方审核，将意见原样写进 `build/review_raw.md`。不依赖特定模型或外部命令行。用户也可以拿审稿包去问任何 AI，把回复贴进这个文件。
3. `video.py review <课> --record` 把意见记进 `review.md`：追加一轮「审稿意见」和一节空的「处理结果」。
4. 在「处理结果」下逐条写：

       1. 采纳：开头改成 NBA 声明，原来的吊箱子画面挪到第 3 句。
       2. 不采纳：审稿建议删掉 compensate，但它是航班延误赔偿这个生活场景的唯一入口；改为压缩到两句。

审稿人的意见不一定对，不采纳要写理由。改完 `plan` 到干净，按用户的审核授权确认；自行审核授权下用 `mark <课> approved --by "用户授权 AI 审核"` 记录依据并继续出片。

## 十一、读音

- 配音默认云健（zh-CN-YunjianNeural）、语速 +20%（由配音会话维护）。edge-tts 不支持自定义 SSML，读音只能靠改写文字。
- 短英文夹在中文中不清楚时，先试真实使用片段；词素可以由画面呈现，声音讲清关系，不必逐个当作独立英语词念。历史词形保留在素材或必要画面中，不用为转写通过堆拼读。检查原始转写，重复幻觉或模糊相似度通过都不能单独证明读音正确。
- 两三个字母的前缀（at、ad、dis、sub）在混合中英文配音里容易误读；云健还会把单独念的 im 读成 "I'm"（`check` 不查 3 个字母以内的词），可写 `say_as: im → i、m`：直接写成要念的样子，或在文件头 `say_as` 里替换，例如 `say_as: retractable → re-tractable；or → O R`。只影响配音，字幕不变。
- 出片后用 `video.py check <课>` 回听检查（需要 `pip install faster-whisper`；默认 large-v3-turbo 模型，首次自动下载约 1.6 GB）。它把每句配音转写回文字：
  - 第一遍不给提示，按拼写相似度和发音骨架（去元音、同音字母归并，append 与 "up and" 算对上）比对；
  - 没对上的词第二遍作为热词再听；两遍都没对上 → **可能读错**；只有第二遍才对上 → **读得可能不够清楚**（提示会让识别偏向预期词，所以不算通过）；
  - 3 个字母以内的词（dis、sub、ad 这类前缀）不查，Whisper 在中文语境里本来就听不准。
- 确认读错的，在文件头 `say_as` 里加替换，重新 `plan` → 按授权审核并 `mark` → `render` → `check`。`say_as` 也算脚本内容，每次修改都要记录新指纹。
