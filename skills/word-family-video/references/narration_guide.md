# 解说词写作指南（projects/<课>/narration.json）

解说词是这个项目里**唯一需要你写的东西**。画面、版式、动画、字幕、时长控制全部自动。
先运行 `init` 生成草稿（由课程卡片自动拼出来，能用但书面腔重），再按本指南逐段改写。

## 一、文件结构

```jsonc
{
  "order": ["contract", "attract", "extract", "distract", "subtract", "retract"], // 重要性排序：最常用、最重要的在前
  "opening": ["拖拉机，英文叫 tractor。", "你有没有想过，它为什么叫「拖拉」机？", "……"],
  "anchor":  ["记住这个画面：一个人，拉着一根绳子。", "接下来的每一个词，都是这个人在拉，只是换了个方向。"],
  "words": {
    "attract": [
      ["先往自己这边拉。", "at 是 ad 的变体，表示朝向，加上 tract，拉。"],          // 第一段：过渡 + 词素
      ["字面意思就是，把东西往自己这边拉。", "把别人的目光、心思往自己这边拉，这不就是吸引吗？"]  // 第二段：画面 → 词义
    ]
  },
  "finale":   [["回到开头……"], ["……这不就是火车吗？"]],      // 结构同 words 里的一项
  "map":      ["我们把它们串起来。", "往自己这边拉，是 attract；往两边拉，是 distract；", "……"],
  "traps":    ["顺便提个醒：track ……"],                     // 可选
  "transfer": [["最后留三个词……", "暂停一下，想好了再往下看。"], ["protract，往前拉长时间，是拖延。", "……"]],
  "outro":    ["下次再碰到带 tract 的词，先想想那个拉绳子的人：他在往哪边拉？"],
  "say_as":   { "retractable": "re-tractable" }            // 只改配音、不改字幕，用来修正读错的英文词
}
```

- `words` 里的键必须和课程的主词一一对应，每个词是**两段**：`[[第一段…], [第二段…]]`。
  第二段第一句开始时，画面上会升起单词本身——所以**第一段不要说出单词的意思**，留给第二段揭晓。
- `map` 每一句里写到哪个英文词，家族图上那个词就在这一句开始时点亮。所以每个主词都要在 map 里出现一次，拼写和课程一致。
- `transfer` 也是两段：第一段出题（题目会一起出现），第二段每句对应一道题的答案，按题目顺序写。

## 二、怎么写得像人在讲（逐条检查）

1. **一句只说一件事，20 字左右，最长不超过 40 字。** 超长的句子 `plan` 会提醒。念起来要有呼吸。
2. **先画面，后词义。** 第二段的顺序固定：字面画面 → 生活场景 → 「这不就是……吗？」 → 一个真实用法。
3. **反问是推理工具。** 「这不就是吸引吗？」让听的人自己完成最后一步，每个词至少用一次。
4. **过渡句承接方向变化**：「如果不是往一个方向拉，而是两股力往两边拉呢？」不要写「下面看 distract」。
5. **变体只讲一次、讲清原因**：第一次出现时说「at 是 ad 的变体，碰到 t 就跟着变成 t，为了顺口」。
6. **英文词直接写，不加引号、不加音标。** 前缀的连字符会自动去掉（at- 读作 at）。
7. **不念括号、不念符号。** 草稿里括号内容已自动去掉；自己写时也不要写「（ad- 的变体）」这种只适合看的注释。
8. **第二段控制在 3 句以内。** 想多讲的搭配、派生词，网页版里都有，视频只讲最有画面感的一个。
9. **不照搬卡片原文。** 卡片是给眼睛看的，解说词是给耳朵听的：把「v. 收缩；订立合同」改成「这是收缩……这就是合同」。

## 三、时长：5 分钟以内

- 目标 ≤ 4 分 50 秒，硬上限 5 分钟。`plan` 会真正合成配音、量出每句时长，再自动删减：
  1. 先删「形近陷阱」单元，2. 再删「迁移题」单元，3. 最后按 `order` 从后往前删主词（最多删到剩 4 个）。
  删掉的东西网页版里都还在，被删的词仍显示在家族图上。
- **所以 `order` 一定要排**：最常用、最有代表性的词放前面。拿不准时，按日常阅读中碰到的频率排。
- 删词以后，被删词后面那张卡的过渡句可能接不上了（例如它说「再换个方向」，但前一个方向没讲）。`plan` 会提示，你要回去改那句过渡。
- 删减后仍超过 5 分钟：缩短句子，每个词第二段最多 3 句。

## 四、读音

- 配音默认用微软 edge-tts 的「云健」（zh-CN-YunjianNeural，用户试听选定），可用 `--voice` 换。edge-tts 不支持自定义 SSML，没法逐词标音素，读音只能靠改写文字修正。
- **两三个字母的前缀（at、ad、dis、sub）谁都读不准、也听不准**：任何 TTS 都没法判断该读成字母还是音节。想让它清楚，就在解说词里直接写成要念的样子，或在 `say_as` 里替换。
- `check` 命令（需要 `pip install faster-whisper`；默认 large-v3-turbo 模型，首次自动下载约 1.6 GB）把每句配音转写回文字：
  - 第一遍不给提示，按拼写相似度和发音骨架（去元音、同音字母归并，append 与 "up and" 算对上）比对；
  - 没对上的词第二遍作为热词再听；两遍都没对上 → **可能读错**；只有第二遍才对上 → **读得可能不够清楚**（提示会让识别偏向预期词，所以不算通过）；
  - 4 个字母以内的词不查。
- 确认读错的，在 `say_as` 里加替换：`"retractable": "re-tractable"`、`"or": "O R"`。只影响配音，字幕不变。改完重新 `render` 再 `check`。

## 五、开场怎么讲（内容第一）

开场类型在课程的 `opening.type` 里（见 word-family 的 `references/openings.md`）。解说词的开场按类型套句式，**最多 4 句**，最后一句把听众引向母画面：

| 类型 | 第一句怎么起 | 例 |
|---|---|---|
| name 熟词拆名 | 「X，英文叫 Y。」+「你有没有想过，它为什么叫 X？」 | 拖拉机，英文叫 tractor。你有没有想过，它为什么叫「拖拉」机？ |
| scene 生活场景 | 「你在 ××（地方）见过这块牌子/这个按钮吗？」 | 在机场取行李，你见过这块牌子吗？上面写着 Baggage Claim。 |
| pair 双词矛盾 | 「为什么 A 是……，B 却是……？」 | 为什么 depend 是依靠，spend 却是花钱？ |
| polysemy 一词多义 | 「X 怎么既是……，又是……，还能是……？」 | course 怎么既是路线，又是课程，还能是一道菜？ |
| news 时事 | 「最近（日期/媒体）有一条新闻……」，只说事实不评论 | 十月下旬，好几家媒体的标题里都出现了同一个词…… |
| pop 品牌/游戏 | 「玩过/用过 X 吗？它的全名是……」 | 玩过 CS:GO 吗？它的全名是 Counter-Strike。 |
| story 想象小剧场 | 「想象一下……」，一个荒诞好记的小画面 | 想象一下，你要坐下的地方，多了一条蛇…… |
| visual 视觉谜题 | 「看这块招牌，是不是写错了？」 | 这栋楼上写着 BVILDING，是不是写错了？ |

- 有开场照片时，第一句就指向照片：「你看这张照片……」「照片里这台……」，让画面和声音对上。
- 开场里抛出的问题，要在最后一张卡或 finale 回答，并在那句解说里点明「回到开头」。
