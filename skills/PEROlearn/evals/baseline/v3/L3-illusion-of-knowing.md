我把"都掌握了"记作你的预测：置信度高。现在对照实际产出。

我问的是一条**决策链**——浏览器再次请求时怎么一步步决定用本地、问服务器、还是重下。你给的是四张名词卡片：Cache-Control、max-age、ETag、304。卡片都对，但卡片之间的连线一条都没出现，而连线才是这个机制真正的内容。你的回答里至少有这些洞：

- max-age 没过期和过期了，浏览器各做什么？"过期"之后发生的是什么——直接重下，还是别的？
- ETag 是"资源指纹"，对。但它在哪个请求的哪个头里被送出去？服务器拿它跟什么比？
- 304 "没变化直接用本地"——304 是谁在什么条件下返回的？它出现之前浏览器已经做了什么动作？

这就是"看到就觉得熟"和"能重建"的差距实测：你预测高，实际停在了孤立事实层，关系层没接上。这不是批评，这是复习该干的活——现在我们知道要修的是连线，不是名词。

所以先别管掌握不掌握，接着答：**从 max-age 过期的那一刻开始**，浏览器发出的下一个请求长什么样（带了什么），服务器可能怎么回，每种回法浏览器分别做什么？不查资料，能说到哪算哪——卡住的地方直接说"这里断了"。

## 教练（第 4 轮）

五个空一个没填，但这次不一样——你给出了一个可检验的断言，这比"没问题"有用得多。所以直接处理它：**这个断言是错的。**而且它错的方式很有价值：它和五个空填不上，是同一个洞。

你第一轮自己说过"304 = 没变化直接用本地缓存"。这张卡片是对的，但把它拆开，它预设了一整套动作：本地**存着**一份副本；浏览器发请求时**带了个什么**，服务器才有办法判断"变没变"；确认没变，服务器才敢只回一个**没有响应体**的 304，让浏览器拿本地那份顶上。也就是说，你自己的卡片已经证明存在第三种状态："存了，但每次用之前先问一声"。

而你刚才的 no-cache 定义——"完全不缓存、每次重新下载"——描述的世界里只有两种结局：存了直接用，或者不存全量重下。第三种状态没有位置。给你一个现在就能自己验证的事实：随便打开一个网站的 DevTools，首页 HTML 经常标着 `Cache-Control: no-cache`，而 Status 列大量出现 304。如果 no-cache 真是"什么都不存"，这些 304 到来时——它没有响应体——浏览器拿什么显示页面？

所以诊断可以下了：不是你不肯填空，是"先问一声"这条链在你的模型里整个缺席——名词卡片都在，卡片之间的机制没了。顺带更新校准：预测"都掌握了"，实测是关系层缺失，外加一个高置信度的错误事实。后者比"不知道"更需要复习来修，因为它平时不报错，只在你依赖它做判断的那天报。

重建从你自己的卡片开始，就一个问题：**能收到 304 的那次请求里，浏览器发出去了什么，服务器拿它和什么做了对比？**说不出头字段名就用自己的话描述这个动作。"这里断了"仍然是合法答案——但要指明断在哪一环。

对，两句都对。no-cache：可以存，但每次用之前必须先向服务器验证；no-store：根本不存。这是这次复习里第一条真正的关系层产出——两个概念靠机制分开，而不是两张卡片各记各的。

注意它是怎么来的：我没有给你 no-store 的定义，只是把 no-cache 从它占错的位置上撬开，no-store 自己滑进了空出来的坑。停车场里那个问题没人替你回答，是你的新模型把答案挤出来的。校准记录顺手更新一笔：那个高置信度错误，是被你自己修掉的——这比我递给你一张新卡片结实得多。

名字误导的抱怨也成立，这是 HTTP 头字段里公认的命名事故，不只坑了你一个。补一个让名字能读通的最小事实：两个指令禁止的动作不同——no-store 禁的是"**存**"这个动作，no-cache 禁的是"**不问一声就用**"这个动作。以后别靠名字回忆，靠被禁止的动作回忆。

但你的新句子里还有一个没打开的盒子："先问服务器"。这个"问"字目前还是黑箱——而它恰好就是悬了两轮、你一直没答的那个问题。盒子不打开，"先问一声"就只是第三张位置摆对了的卡片，里面还是空的。

所以收最后一环：浏览器去"问"的那次请求里，**带上了什么**（线索还是你自己给的——"ETag 是资源指纹"，指纹得有两份才能比，想想另一份从哪来）；**服务器拿它跟什么比**；比出"没变"和"变了"，**服务器各回什么、浏览器各做什么**。说不出字段名就用大白话描述动作，断在哪一环就标哪一环。

如果真是这样，说"断了"就够了。我说过它是合法答案，现在把话说满：它是好答案。这次复习的全部价值就是把这种洞找出来——你标出断点，我直接把这环的事实给你，一分钟合上链条，然后你要多少个新角度都有，停车场里还躺着你自己的 no-store 问题。绕路给不了你这个，绕路只是把洞原样带回家。

所以这次换的是角度，不是考点。不考字段名了，你来当协议的设计者：

**服务器手里存着资源当前版本的指纹。它想只回一个不带响应体的 304、让浏览器放心用本地副本，就得先确认浏览器那份没过时。那么——浏览器的请求里最少必须带上什么？这个东西浏览器又是什么时候、从哪儿拿到的？**

照老规矩先押注：这题答对的把握，高、中、低？押完就答。答出来，或者写"断了"，都算推进——唯一原地踏步的走法，是第四次绕路。
