## 1. 问题与根因

**解说像机器人**：同一个句式被四处规则强制。word-family `scripts/build.py:182-183`（bridge 无问号即提醒，并建议写「这不就是 X 吗？」）、`references/style_guide.md:27`、video `references/narration_guide.md:36-37`（第二段顺序固定 + 每词至少一次反问），连 `evals/no-narration.json` 都把它当预期行为。结构上 `video.py` 把每个词卡死成 `[[第一段],[第二段]]`，`auto_word` 按卡片字段顺序念。主线也被统一成"换方向"：pend 的真实主线是"挂 → 称 → 付钱"的演变，v1 只能在 dispense 处硬转。

## 3. 工作流程

```
写稿（含自查）→ 自动检查 → 用户审核或明确授权 AI 审核 → 逐条处理 → 确认并记录指纹 → 出片 → 读音与实际成片检查
                                                                    ↑ 看完不满意：改脚本或加批注，回到这里
```

1. **写稿**：按 `references/script_guide.md` 写 `projects/<课>/script.md`，跑 `plan` 改到无错误、无提醒。默认由当前 agent 完成；只有用户允许且环境支持时才并行分工，不依赖固定厂商或模型。
2. **AI 审稿（按用户要求）**：用户要求审稿或授权自行审核时，`video.py review <课>` 生成包含审稿要求、素材与带行号脚本的 `build/review_brief.md`，由当前 agent 或可用的独立审稿方审核。意见写进 `build/review_raw.md`，运行 `review <课> --record` 记进 `review.md`，逐条记录处理结果并修改。没有自行审核授权时仍等待用户确认。
3. **状态**：只有 `draft`（写过或改过）和 `approved`（用户确认，或用户明确授权 AI 审核后通过）。`mark` 维护状态和内容指纹；自行审核用 `mark <课> approved --by "用户授权 AI 审核"` 如实记录依据。最新一轮审稿未处理完时拒绝标记。
4. **出片条件**：approved、指纹一致、没有 `>>` 批注、`plan` 无错误、画面检查通过。失败时说明原因；渲染失败或时长不符保留原成片。常规流程交用户审核，已明确授权自行审核的任务在完成核查后直接出片，不重复请求中间确认。
5. **回头修改**：改字、处理批注或修读音后重新 `plan` 与审核，记录新指纹；自行审核授权持续适用于当前任务的这些修订。不得手改状态或沿用旧指纹。

**命令**（`scripts/video.py`）：`brief` 打印写稿素材（课程事实、可用画面块参数、每个词合法的触发词、时长预算）；`plan` 解析 + 检查 + 配音 + 时间轴 + 试听音频 `build/preview.mp3`，打印节拍表、提醒、未处理批注数；`review` 生成审稿包 / `--record` 记录意见；`mark`；`photo` 搜图或网页截图存进 `projects/<课>/media/` 并打印可直接粘贴的 `[photo]` 行和署名；`status` 列出所有课的状态/时长/批注数；`preview` 生成浏览器实时预览；`stills`；`render`；`check`。取消 v1 的 `init` 与超时自动删减——审的是什么，渲出来就是什么，超时由写稿方在审前删减，记入 `skip`。

## 4. 写稿方法（`references/script_guide.md`）

**先定主线**（写进 `spine`），由词根性质决定：
- 方向型：词根是一个身体动作，前缀是方向（tract、ject、port、press）。同一母画面换方向，方向尽量成对。
- 演变型：词义分几步漂移（pend 挂→称→付钱；sal 盐→薪水）。按阶段分幕，每幕一个 `[title]`。
- 场景型：词根长在某个领域（jud 法庭、port 港口与贸易）。按场景里走一圈来排。
- 对照型：一课围绕反义或易混的成对词（in-/ex-，pre-/post-）。用 `[pair]` 成对讲。

**每个词选一种讲法**：真实事件、物件特写（饮水机 dispenser）、一词多义分叉（contract 收缩/合同）、历史演变（spend ← expendere）、反差（长得像却不同源）、想象小剧场（须标注是联想）、冷知识/数字、两词对照、真实标题或引语。相邻两个词讲法不同，一支视频至少三种；有合适的真实事件就用，没有就不用，不硬凑。

**真实图片**：只给观众在现实里见过、与解说相符的物件或现场配图；优先近期产品、界面、新闻和日常包装，没有数量配额。`video.py photo` 支持 Commons 搜索、网页截图与直接下载；图放在 `projects/<课>/media/`，`> 署名` 必填，出处须核实。

**口播语言**：一行一句配音、不超过 40 字；长短句交替，允许 4–6 字的短句；反问全片不超过 2 次，「这不就是……吗」全片最多 1 次；不用"下面我们来看""接下来是"一类转场套话；不念卡片（不再出现"字面画面："这类标签）。开场按课程的开场类型（word-family `openings.md`）改写成口语，结尾回扣开头并做总结——这两部分保持 v1 的结构。

**事实**：年份、日期、数字、引语、事件必须在所在节拍写 `> 来源：URL（日期）`，来源须经网页搜索或 firecrawl 打开核实；词源说法只能来自课程 JSON 或 word-family 的 `etym.py`（新查的写 `> 来源：etymonline <词>`）；联想写 `> 注：联想`。找不到来源的说法删掉。

**时长**：目标 ≤ 4:50，硬上限 5:00（按当前 +20% 语速）。参考分配：开场 + 母画面约 1 分钟，每词 25–35 秒，回扣 + 家族图 + 结尾约 40 秒。

**交审前自查清单**：开头 10 秒有没有一个具体的东西；主线在节拍标题里看得出来吗；有没有两个词讲法相同；每个事实都有来源吗；屏幕上的字有没有和解说重复；结尾回答了开头的问题吗。

**AI 审稿要点**（`references/review_brief.md`，仅在用户要求审稿时使用）：开头抓不抓人、主线是否贴合词根、每个词讲法是否不同且落到生活或真实事件、口播感与套话、可疑或无来源的说法及与课程词源是否一致、画面块是否用对、时长取舍、结尾是否收住。输出为编号意见，每条含位置、问题、改写示例，最后列"最想改的三处"。

## 5. `script.md` 格式

```markdown
---
lesson: pend
status: draft
spine: 演变——挂 → 挂上秤称 → 称出去付钱
skip: append（时长不够，网页版里有）
say_as: retractable → re-tractable；or → O R
---

## 一场停摆 [event]
> 事件：NBA 官方声明 · 2020-03-11
> 原文：The NBA is {suspending} game play … {until further notice}.
> 来源：https://official.nba.com/nba-to-suspend-season-following-tonights-games/
2020 年 3 月 11 日晚上，NBA 发出一份声明，正文就几行。
最要紧的是这个词：{suspending}。

## suspend [word: suspend]
{sub}，从底下往上；碰到 p，它常常写成 {sus}。
{pend}，挂。
>> 用户批注写在这里
```

- `## 标题 [块]` / `## 标题 [块: 参数]` 开始一个节拍；普通行 = 一句配音；`{…}` = 触发点（字幕和配音里去掉括号）；空行 = 段落停顿；`> 键：值` = 画面数据、来源、注，不念；`>>` = 批注，不念。
- 文件头：`lesson`、`spine` 必填；`status`、`checked` 由工具维护；`skip` 列出没讲的主词及原因；`say_as` 只改配音不改字幕。
- 每个课程主词必须出现在某个 `[word]` 节拍或 `skip` 里。

| 块 | 写法 | 层 | 触发点 |
|---|---|---|---|
| 章节卡 | `[title]` | 整屏 | — |
| 线稿 | `[scene: 词/anchor/opening/finale]` | 右侧舞台 | — |
| 照片 | `[photo: opening]` 或 `[photo: media/文件]` | 右侧舞台；`> 版式：整屏` 时铺满 | —（非课程照片须 `> 署名`） |
| 词素拼合 | `[word: 词]` | 左侧叠加 | `{词素}` 入场，`{变体前的原形}` 先入场后变形，`{整词}` 合拢并出释义 |
| 引文/事件卡 | `[event]` | 整屏 | `{与原文相同的片段}` 高亮；`> 事件`、`> 来源` 必填 |
| 两词对照 | `[pair: A \| B]` | 整屏 | `{A}`、`{B}` 各自出场 |
| 家族图 | `[map]` | 整屏 | 提到哪个词，哪个节点亮 |
| 迁移题 | `[quiz]` | 整屏 | `{答案词}` 揭晓 |

`[word]` 默认用课程主词或 finale 的 `split/parts`；课程外的同族词须有 `> 释义：` 和 `> 来源`，只显示整词不拆。整屏块出现时左侧单词淡出；`scene/photo` 与单词同屏。

**解析报错**指出行号和改法，例如"第 23 行：sup 不是 suspend 的词素，可用：sub、sus、pend、suspend"。
**错误**（`plan` 失败）：未知块或参数、`[event]` 缺来源、`[word]` 触发词非法、主词既没讲也没进 `skip`、含年份/日期/数字的句子所在节拍无来源且该数字不在课程 JSON 中、总时长超过 5:00。
**提醒**：套话超额（见 §4）、连续 3 行前两个字相同、单行超 40 字、全片句长（字数）标准差小于 4、触发点只能估算时刻、同一种构图连续 4 拍以上。照片没有数量提醒。

## 6. 时间轴与配音接口

- 仍按句合成、按文本缓存（音色、语速沿用配音会话的默认）；合成时同时请求 edge-tts `boundary="WordBoundary"`，逐词时间戳与 mp3 一起缓存（试验中 8 个触发点全部精确命中）。触发点先按整词匹配，再按拼接文本匹配，都失败时按字数比例估算并提醒。
- 停顿：句间 0.2 s，段落空行 0.45 s，节拍间 0.45 s，片头 0.6 s，片尾 1.5 s；舞台转场与上一节拍末尾重叠，不额外占时长。
- `plan` 输出 `build/timeline.json`（节拍、句子绝对时刻、触发点时刻、字幕分段）和 `build/preview.mp3`；`render`、`preview`、`stills` 都只读 timeline，不再各自排时间。

## 11. 风险

- 真实事件找不到可靠来源：规则是不用，不允许为了"有事件"降低来源标准。
- 节拍自由度更高，较弱的模型更容易写乱：靠严格解析 + 可执行的报错 + `brief` 给出合法参数 + 样例脚本 + 用户审核兜底。
- 配音本身的平淡感不在本次范围：脚本的长短句交替能缓解一部分，根治依赖配音会话的 TTS 选型。

## 已否决

- **Remotion**：52 秒样片 A/B，逐帧平均像素差 0.1–0.2/255，渲染 48.5 s vs 46.4 s；Remotion 额外 753 MB 依赖；本机预留了 2822–3221 端口，而 Remotion 默认只找 3000–3100，每次都要手动指定端口；线稿是 SVG 字符串，放进 React 只能直接改 DOM，试验中曾因 React 19 每帧重写 innerHTML 导致描画动画失效（可修，但这类坑会一直伴随）。需要 3D、运动模糊、Lottie 类效果时再议。
- **保留单元结构只放开内容**（方案 B）：画面节奏仍是一词一页，演变型主线放不进去。
- **自由讲稿再自动切分**（方案 C）：多一道转换，弱模型易切错，审核对象不清。
